# ダッシュボード画面 Spec

Status: Ready
責任者: TBD
最終更新: 2026-10-10
変更区分: Standard
ロードマップ項目: T-216

## 目的

T-204 の `GET /api/v1/dashboard` を画面として提供し、Member が直近 7 日・30 日の成功率と習慣ごとの内訳、連続実施の状況を一目で振り返れるようにする。数値の定義は集計定義(D-13、[statistics-dashboard.md](statistics-dashboard.md))に一致させ、表示だけを担う。ストリークは強調しすぎず、失敗後の復帰を妨げない控えめな扱いにする(検証すべき仮説:「streak を強調しすぎない表示が復帰率を改善する」)。基盤は [web-ui-foundation.md](web-ui-foundation.md) に従う。

## 成功指標

- 記録の後にダッシュボードを開くと、成功率・件数・ストリークが集計定義どおりの値で反映される(E2E)。
- 成功率は「成功 ÷ (成功 + 未実施)」であり、スキップと今日の未記録(保留)を分母に含めないことが画面上の説明と数値の両方に一致する(Unit、E2E)。
- 成功率・件数の状態を色だけに依存せず、数値とラベル(文字)で伝える(E2E、a11y)。
- 記録がない・習慣がない場合は、エラーではなく空状態を表示する(E2E)。
- 他ユーザーの集計は表示されない(E2E)。

## 範囲

- 画面 `/dashboard`(`(onboarded)` 配下)。ナビゲーションに「ダッシュボード」を追加。
- 全体(直近 7 日/30 日): 成功率、件数内訳(成功・未実施・スキップ・保留)。
- 習慣ごと: 名前(詳細へのリンク)、種類、直近 7 日/30 日の成功率と件数、現在の連続回数と最長。
- 集計定義の簡潔な説明(成功率の分母、保留・スキップの扱い、ストリークの数え方)。
- 空状態(習慣なし)と、記録なし(成功率 `null`)の表示。
- 記録操作(T-215)の成功時にダッシュボードの cache を無効化する。
- 文書: 本 Spec、Plan、`docs/09`。

## 対象外

- 新規 API・DB の変更(Migration なし)。期間の選択、グラフ(時系列)、エクスポート。
- 習慣のアーカイブ済みの集計(STAT-INV-004: active のみ)。
- 週次レビュー(T-301 以降)。

## 機能要件

### DSH-001 取得と状態

- `GET /api/v1/dashboard` を `useQuery` で取得する。取得中は `loading`、失敗は再試行できる `error`、`401` は共通処理で login へ。
- 習慣が 0 件(`habits` が空)なら空状態「進行中の習慣がありません」と、習慣を作る導線(`/habits/new`)を表示する。

### DSH-002 全体の集計

- 直近 7 日と直近 30 日のそれぞれについて、成功率と件数内訳(成功・未実施・スキップ・保留。0 も表示)を表示する。期間は `from`〜`to` を日付で併記する。
- 成功率は整数%で表示する(DSH-INV-002)。`null`(分母 0)は「まだ集計できません」と表示し、0% と区別する。

### DSH-003 習慣ごとの内訳

- active な習慣ごとに、名前(`/habits/{id}` へのリンク)、種類ラベル、7 日・30 日の成功率と件数内訳、現在の連続回数・最長の連続回数を表示する。並びは API の順(作成が古い順)。
- ストリークは「現在 N 回連続(最長 M 回)」のように控えめな文言で、成功率より目立たせない。単位は「回」(予定された機会の数。日数ではない)。

### DSH-004 集計定義の説明

- 画面に折りたたみ(`details`)で次を説明する: 成功率 = 成功 ÷(成功 + 未実施)。スキップは分母に含めない。今日の未記録は保留として分母に含めず、連続も切らない。過去の未記録は未実施として扱う。連続回数は成功で増え、未実施で 0 に戻り、スキップと保留では変わらない。

### DSH-005 キャッシュ

- ダッシュボードの query key は `["dashboard"]`。記録(T-215)の成功時に無効化し、画面表示時は常に再取得する(古い集計を残さない)。

## 業務ルールと不変条件

- DSH-INV-001(業務ロジックを持たない): 集計は server(Domain)が計算する。client は表示用の整形のみで、成功率・件数・ストリークを再計算しない。
- DSH-INV-002(率の整形): 整数%に丸めるとき、`rate < 1` の値を「100%」に、`rate > 0` の値を「0%」にしない(境界で実際の状態を誤解させない)。`1` は 100%、`0` は 0%。
- DSH-INV-003(色に依存しない): 率・件数・状態は数値とラベルで示す。装飾的な棒(`meter`)があっても同じ情報が文字にある。
- DSH-INV-004(所有者限定): 画面は `GET /api/v1/dashboard` のみ。他ユーザーを指定する手段がない。
- DSH-INV-005(個人情報の非ログ): 習慣名をログ・URL に出さない。React のエスケープで描画する。

## 受け入れ基準

```gherkin
Scenario: 記録がダッシュボードに反映される
  Given 毎日予定の習慣があり、昨日と一昨日が success、3 日前が missed、今日は未記録
  When /dashboard を開く
  Then 直近 7 日の成功率は 33%、件数は 成功 2 / 未実施 4 / スキップ 0 / 保留 1
  And 現在の連続は 2 回
  When /today で今日を「できた」に記録して /dashboard を開き直す
  Then 成功 3 / 未実施 4 / 保留 0、成功率は 43%

Scenario: スキップと保留は成功率の分母に含まれない
  Given 昨日が skipped の習慣
  When /dashboard を開く
  Then スキップ 1 と表示され、成功率の分母に含まれない

Scenario: 空状態
  Given 進行中の習慣がない Member
  When /dashboard を開く
  Then 「進行中の習慣がありません」と習慣を作る導線が表示される

Scenario: 記録がない習慣は率を出さない
  Given 作成直後で予定機会が今日だけの習慣
  When /dashboard を開く
  Then 成功率は「まだ集計できません」と表示される(0% ではない)

Scenario: 他ユーザーの集計は見えない
  Given Member A に記録がある
  When Member B が /dashboard を開く
  Then B 自身の集計(空状態)のみが表示される
```

## 失敗・境界ケース

- 取得失敗: エラー表示と再試行。`401` は login へ。
- 習慣はあるが期間内の予定機会が 0 件: 件数 0、成功率「まだ集計できません」。
- 整数%の境界: 0.995 → 99%、0.004 → 1%、1 → 100%、0 → 0%(DSH-INV-002)。
- 深夜 0 時をまたいで開いたままの画面: 取得時点の集計を表示する。再読み込みで更新される。

## セキュリティとプライバシー

- 収集データ: なし(表示のみ)。習慣名は React のエスケープで描画。ログ禁止: 習慣名、集計値。
- IDOR は API の所有者限定に依存。E2E で 2 ユーザーを確認する。
